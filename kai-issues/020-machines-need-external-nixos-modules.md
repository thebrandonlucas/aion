# Feature: machines need external NixOS modules

## Limitation on Kai master (`d4a7fdd`)

A machine can enable a module already present in NixOS by naming one of its services, or compose a module generated by Kai's fixed executable-service command. It cannot import a NixOS module output from a locked flake source.

Paseo publishes `nixosModules.paseo`. Its module owns the daemon's service, user, home, and package integration, so reproducing it as a Kai generated service would duplicate upstream behavior and require broader service features.

## Needed capability

Let a machine import one module output from a locked flake. For example, the design needs an equivalent of:

```text
external module paseo {
  source: paseo
  attribute: "nixosModules.paseo"
}

machine server {
  modules: ["paseo"]
}
```

The exact syntax can differ. Kai only needs to:

- reuse the source revision in the Kaifile lock;
- select and import the module into the generated machine;
- report a missing or invalid module during the machine build; and
- compose it for `machine`, `image`, and `deploy` commands.

Configuring module options is a separate capability. A generic host-extension framework and arbitrary Nix expressions are not required for this recipe.
